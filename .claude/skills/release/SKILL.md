# إصدارٌ جديد من بُغية

الإصدارُ يصل إلى كلّ من نصّب البرنامج عبر زرّ «حدّث الآن»؛ فالخطأ فيه يصل إلى الناس كلّهم. لا تتجاوز خطوة.

## 1. حدّد الرقم والنوع (اسأل المطوّر إن لم يذكرهما)
- **الرقم** بصيغة `0.9.7`: الأخيرُ للإصلاحات والميزات الصغيرة، والأوسطُ للتغيير الكبير.
- **عاديّ أم تجريبيّ؟** الفرقُ في الوسم وحده: `v0.9.7` أو `v0.9.7-beta1`. والرقمُ في الملفّات `0.9.7` في الحالين. والتجريبيّ يُنشر «prerelease» فلا يُعرض في شريط التحديث للناس.
- ما الذي يدخل الإصدار؟ اقرأ أقسام `اقرأني.md` التي عنوانها «(لم تُنشر بعد)»، و`git log` منذ آخر وسم (`git describe --tags --abbrev=0`)، واعرضها على المطوّر ليؤكّد.

## 2. ارفع الرقم في المواضع كلّها
```
python .claude/skills/release/scripts/version.py --set 0.9.7
```
يكتب الرقم في `app/common.py` و`installer/bughya.iss` و`assets/version.txt` (بأرقامه الأربعة) ثمّ يتحقّق كما يتحقّق `release.yml`. وبلا `--set` يتحقّق فقط. لا تعدّل هذه الملفّات بيدك.

## 3. حدّث `اقرأني.md`
- كلُّ قسمٍ «(لم تُنشر بعد)» دخل الإصدار يصير عنوانُه «(الإصدار 0.9.7)».
- ما لم يدخل يبقى كما هو.
- حدّث «ما بقي» إن أُنجز منه شيء.

## 4. افحص
- `selftest.py` يجب أن ينجح كلُّه (وفي لينكس يُستثنى تنبيهُ القراءة الآليّة). وهو نفسُه ما يشغّله `release.yml` قبل البناء، فإن فشل هنا فشل هناك.
- إن مسّ الإصدارُ القراءةَ أو البحث فتأكّد أنّ مهارة `measure` طُبّقت وأنّ أرقامها في `اقرأني.md`.
- البناءُ نفسه (`build_exe.bat` والمثبِّت) لا يُجرَّب في لينكس؛ يجرّبه GitHub Actions. فإن أُضيفت وحدةٌ جديدة يستدعيها البرنامج فتأكّد أنّها في `--hidden-import` في `build_exe.bat`.

## 5. أودِع
رسالةُ الإيداع على نسق المستودع:
```
الإصدار 0.9.7: <عنوان الميزة الأبرز>

<فقرةٌ قصيرة: ما الجديد ولماذا>
```
على الفرع المخصّص للجلسة، ثمّ طلبُ دمج (PR) إن طلبه المطوّر. **الوسمُ يُوضع على `main` بعد الدمج**، لا على الفرع.

## 6. اكتب ملاحظات الإصدار
ينشرها `release.yml` بملاحظاتٍ آليّة (`--generate-notes`)، ثمّ يستبدلها المطوّر بنصٍّ يكتبه. فاكتب له المسودّة في ملفٍّ يلصقه في صفحة الإصدار. وشريطُ التحديث في البرنامج يعرض **عناوين `###`** منها (أوّلَ خمسة، دون ما فيه «التثبيت» أو «التنصيب»)؛ فالعنوانُ يجب أن يُفهم وحده.

النسق (من إصدار 0.9.6):
```
## بُغية 0.9.7

### <الميزة بلغة الباحث، لا بلغة المبرمج>
<جملةٌ عن فائدتها له>

- <ما يراه ويفعله، خطوةً خطوة>
- <ما يبقى كما هو: كتبُه ومسوّداتُه ومكتبتُه>

### التثبيت
اضغط **«حدّث الآن»** في الشريط أعلى البرنامج. أو:

1. نزّل **`Bughya-Setup-0.9.7.exe`** وشغّله فوق النسخة السابقة. مكتبتك وبياناتك تبقى كما هي.
2. أو نزّل **`Bughya-windows-0.9.7.zip`**، وفُكّ ضغطه، وشغّل `Bughya.exe` دون تثبيت.

البرنامج غير موقَّع رقميًّا، فقد يظهر «ويندوز حمى جهازك»: اضغط **مزيد من المعلومات ← تشغيل على أي حال**. وللتأكد من الملف قارن بصمته بما في `SHA256SUMS.txt`.

**التغييرات كاملة:** https://github.com/omar209520-bot/bughya/compare/v0.9.6...v0.9.7
```
عربيّةٌ فصيحةٌ قصيرة، بلا أسماء ملفّاتٍ ولا مصطلحاتٍ تقنيّة في غير قسم التثبيت. ولا تذكر ميزةً لم تدخل الإصدار.

## 7. الوسم والنشر — بإذن المطوّر الصريح وحده
بعد دمج الفرع في `main`، إمّا:
```
git checkout main && git pull
git tag v0.9.7 && git push origin v0.9.7
```
وإمّا من GitHub: **Actions ← Release ← Run workflow** واكتب الوسم.

فيبني GitHub Actions البرنامجَ والمثبِّت وينشرهما. إن فشل البناء بخطأ «لا يطابق» فالرقمُ مختلفٌ بين المواضع: شغّل `version.py` ثمّ أصلح وأعد الوسم.

بعد النشر: ذكّر المطوّر أن يلصق الملاحظات في صفحة الإصدار، وأن يجرّب «حدّث الآن» من النسخة السابقة على جهازه.
